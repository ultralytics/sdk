# AGENTS.md

This file provides guidance to AI coding agents (Claude Code, etc.) when working with code in this repository. CLAUDE.md is a symlink to this file.

`ultralytics/sdk` publishes `ultralytics-platform` (PyPI, AGPL-3.0, Python >=3.11, one runtime dependency: `httpx`): typed sync/async Python clients for the Ultralytics Platform API plus the unified `ul` CLI. Almost everything under `sdk/python/` is generated by the `ultralytics/openapi` generator from the pinned contract snapshot `openapi.json`; the only hand-written Python is root `cli.py`, root `auth.py`, and `tests/`. The `ultralytics` package depends on this one (`ultralytics-platform>=0.1.32` in its `pyproject.toml`, lazily re-exported from `ultralytics/__init__.py`) and `yolo login` calls `Platform(api_key=..., base_url=..., timeout=...).account.summary()`, so the public client surface is a compatibility boundary.

## Core Principles (CRITICAL)

**Less is more. The simplest solution is the best solution.** The action hierarchy for every change: **Delete > Replace > Add**.

1. **Solve at the owner**: Put behavior in the code path that owns or observes it. For fixes, never guard a symptom with a staleness check, initialization flag, skip-first-call branch, or `try/except` around broken logic; relocate the trigger and delete the wrong path. For features, extend the existing owner rather than creating a parallel abstraction.
2. **Search and reuse first**: Search the whole repository before creating a feature, component, helper, workflow, or utility. Reuse or adapt what exists, consolidate in-scope duplication in the shared owner, and delete duplicate paths. Three similar lines beat a helper nobody else calls.
3. **Delete and modify existing code before creating new code**: Bugfixes are net-negative by default unless deletion and relocation are demonstrably impossible. A new file must first prove it cannot fit cleanly in an existing owner.
4. **Keep scope minimal**: Implement only the simplest complete solution. Avoid impossible-state handling, speculative flags, compatibility shims, policy scaffolding, and unrelated cleanup. Tests are out of scope by default — rely on existing coverage and focused validation; only an uncovered, high-risk regression path justifies minimal new test code.
5. **Ship zero-regression, production-ready changes**: Understand what you remove instead of retaining broken code as insurance. Remove unused imports, functions, types, files, and comments; run relevant cleanup checks; and thoroughly debug and validate the changed owner. Do not break existing features or workflows unless the PR intentionally removes them with evidence.

**Review gate:** for every addition, the reviewer decides whether deleting or changing existing code would have fixed the problem instead — if it would, that is a blocking finding. A missing or thin PR description is never itself a finding.

NEVER push to `main`. NEVER force push. Always start work in a new git worktree (`git worktree add`) on a feature branch and open a PR — never edit the primary checkout directly, it may hold in-flight work.

## PR Workflow

After opening a PR:

1. Wait for the automated PR review and auto-format commit from Ultralytics Actions (`format.yml`), then pull and address every finding.
2. Review the full diff in-session against the Core Principles, performance, and the review gate above, then batch the fixes into one commit and push. After each round of bot or human commits, pull and resume the same reviewer on `<last-reviewed-sha>..HEAD` plus anything that delta could have invalidated. Repeat until the local head matches the live head.
3. Hand off or merge only on a clean final pass: one cold full-diff review returning LGTM with no findings, on a head that is still live at merge time.
4. Never fight other commits: Ultralytics Actions pushes auto-format and header commits, and multiple users may work on the same PR. `git pull --rebase` before pushing; never reset or revert commits you did not author.
5. After the PR merges, clean up: remove local worktrees and branches for it, then `git checkout main && git pull`.

## Commands

```bash
# Dev install into an activated virtualenv (Python >=3.11). tests/test_cli.py spawns
# `python -m ultralytics_platform.cli`, so the package must be installed, not just importable from the checkout.
uv pip install pytest jsonschema referencing ./sdk/python

# Unit suite exactly as CI runs it (loopback HTTP server + httpx.MockTransport; no network, no credentials)
pytest tests -v
pytest tests/test_cli.py -v                   # single file
pytest tests -k test_api_error_details -v     # single test

# CI validation steps (ci.yml "Validate Python SDK"; ruff is pinned, there is no root ruff config, keep --line-length 120)
sha256sum --check openapi.sha256
uvx ruff@0.16.2 format --check --line-length 120 sdk/python tests cli.py auth.py
uvx ruff@0.16.2 check sdk/python tests cli.py auth.py
python -m compileall -q sdk/python/src
uv build --project sdk/python

# Regenerate sdk/python after changing openapi.json, openapi.config.json, cli.py, auth.py, or README.python.md.
# .generator/ is gitignored; always use the generator's main branch, never a SHA or tag. Needs bun and uvx.
git clone https://github.com/ultralytics/openapi.git .generator
export OPENAPI_CONFIG="$PWD/openapi.config.json"
(cd .generator && bun install --frozen-lockfile && bun run generate)
rsync --archive --delete .generator/generated/python/ sdk/python/
diff --recursive --unified sdk/python .generator/generated/python   # CI's drift check; must print nothing

# After replacing openapi.json by hand (the Live job normally does this), re-pin the hash
sha256sum openapi.json > openapi.sha256

# CLI smoke test. macOS ships an unrelated /usr/bin/ul, so use the venv's bin/ul or the module form.
ul version && ul cloud --help
python -m ultralytics_platform.cli cloud account summary   # needs ULTRALYTICS_API_KEY or a key saved by `yolo login`
```

CI checks Python 3.11 and 3.14 on Ubuntu. It verifies the versioned Platform contract against `openapi.sha256`, regenerates the Python output from the `main` branch of `ultralytics/openapi`, fails on generated drift, and then runs the Python checks above plus a Git subdirectory install (`uv pip install "git+file://$GITHUB_WORKSPACE@<sha>#subdirectory=sdk/python"`). The `Live` job ("Full API lifecycle") runs on every `main` ref build (pushes and the daily cron) and on manual dispatch — never on pull requests — downloads the upstream contract, regenerates the SDK, opens and merges the contract-update PR on green checks without human involvement, and only then runs the production canary in `tests/live_readonly.py`, so a canary failure never blocks the SDK from tracking the contract. New endpoints do not need canary coverage; add it only when live behavior is worth guarding.

Workflows in `.github/workflows/`:

- `ci.yml` (CI): `Test` matrix (3.11, 3.14) on PRs, `main` pushes, daily cron `0 0 * * *`, and manual dispatch — contract hash check, `bun run generate` in `.generator/` with `OPENAPI_CONFIG` pointing at this repo's config, `diff --recursive` drift gate, ruff, compileall, wheel build (asserts the wheel carries `.dist-info/licenses/LICENSE`), Git-subdirectory install, `pytest tests -v`. `Live` (`concurrency: openapi-sync`): fetches `upstream` from `openapi.config.json` (`https://platform.ultralytics.com/openapi.json`), rewrites `openapi.json` + `openapi.sha256` when it changed, sets or clears `python.version` (see Releases below), regenerates, and if anything under `openapi.config.json`, `openapi.json`, `openapi.sha256`, or `sdk/python` changed it pushes branch `automation/openapi-<12-hex hash>`, opens the PR "Update Platform API contract" as `github-actions[bot]`, waits for the `CLA`, `Test (3.11)`, `Test (3.14)`, `actions`, and `Full API lifecycle` checks, and squash-merges with `--admin --match-head-commit`. It then installs `./sdk/python` and runs `python tests/live_readonly.py` with the `ULTRALYTICS_API_KEY` secret.
- `format.yml` (Ultralytics Actions): runs with `python: false`, `prettier: false`, `links: false`; it checks spelling (codespell), auto-labels, and posts the AI PR summary. Python formatting is not applied by the bot in this repo — CI's pinned `ruff@0.16.2` is the gate, and the generator formats its own output (`bun run generate` ends with `ruff format` + header insertion).
- `publish.yml` (Publish to PyPI): triggered by a successful CI `workflow_run` for a push to `main` (or manual dispatch on `main` by glenn-jocher with the `pypi` input). `check` compares `sdk/python/pyproject.toml` against PyPI (`check_pypi_version` from `ultralytics-actions`), enforces `MAJOR.MINOR.PATCH`, and publishes whenever local > online (no patch-gap limit, because contract versions can skip numbers); then `build` (`python -m build sdk/python`) → `publish` (trusted publishing, one retry after cleaning `*.publish.attestation`) → `release` (tags `v<version>`, `ultralytics-actions-summarize-release`) → `sbom` (SPDX upload) → `notify` (Slack).
- `cla.yml`: CLA check on `pull_request_target` and `recheck` / signature comments.
- `.github/dependabot.yml`: weekly `github-actions` bumps.

## Architecture

- The API/docs/SDK repository chain always follows `main`: cross-repository `ultralytics/openapi` checkouts must use `ref: main` and must never pin a commit SHA or tag.

This repository contains generated SDKs for Ultralytics products. `openapi.config.json` defines the consumer configuration; `openapi.json` and `openapi.sha256` pin the contract. All of `sdk/python/` is generated, committed, and drift-checked; never edit it manually. Maintain CLI behavior in root `cli.py` and shared credentials in `auth.py`. The generator copies these sources into the package, emits multipart binary-field metadata in `_cli_metadata.py`, and registers `ul`; `cli.py` owns the launcher. The CLI discovers operations, types, and help from SDK signatures and docstrings. After changing sources, configuration, or contract, regenerate with an `ultralytics/openapi` main checkout at `.generator/` and copy `.generator/generated/python/` to `sdk/python/`. `tests/` owns consumer checks; `format.yml` applies Ultralytics Actions, `ci.yml` owns regeneration and package validation, and `publish.yml` owns releases and PyPI publishing.

Paths below are relative to the repository root; `pkg/` abbreviates `sdk/python/src/ultralytics_platform/`.

**Inputs the generator reads** (`ultralytics/openapi` `lib/config.ts`, `lib/generators/python.ts`, `scripts/generate.ts`): `openapi.config.json` → `source` (`openapi.json`, copied to `.generator/public/openapi.json` by `bun run sync`), `upstream` (used only by the Live job), `apiKey.environment` (`ULTRALYTICS_API_KEY`), `header` (license header stamped onto every generated `.py`/`.toml` by `scripts/headers.ts`), `license`, and `python.*`: `client` (`Platform`), `package` (`ultralytics_platform`), `project` (`ultralytics-platform`), `requiresPython`, `classifiers`, `keywords`, `description`, `authors`/`maintainers`, `readme` (`README.python.md`, copied verbatim to `sdk/python/README.md`), `authProvider` (`auth.py` → `pkg/_auth.py`), `cli` (`command: "ul"`, `source: "cli.py"` → `pkg/cli.py`, `pkg/_cli_metadata.py`, and `[project.scripts] ul = "ultralytics_platform.cli:main"`), and optional `version` (package version; when absent the contract's `info.version` is used). Everything else in `sdk/python/` is a pure function of `openapi.json`.

**Generated package** (`pkg/`):

- `__init__.py` exports exactly `NOT_GIVEN`, `NotGiven`, `APIConnectionError`, `APIError`, `AsyncPlatform`, `Platform`.
- `client.py` / `async_client.py`: `Platform(*, api_key=None, base_url="https://platform.ultralytics.com", timeout=60.0, max_retries=2, http_client=None)` resolves the key with `_resolve_api_key` and attaches one resource object per contract tag as attributes (`account`, `billing`, `datasets`, `deployments`, `explore`, `images`, `storage_integrations`, `models`, `exports`, `projects`, `training`, `lifecycle`, `upload`). Context managers close the underlying `httpx` client.
- `_client.py`: `_resolve_api_key(api_key)` — explicit value (even `""`, which disables auth) → non-empty `ULTRALYTICS_API_KEY` → `get_api_key()` from `_auth.py`. `SyncAPIClient.request` / `AsyncAPIClient.request` build the URL from `base_url` (and a per-operation `server` override), add the header from the operation's `auth=("Authorization", "Bearer ")` tuple only when a key is set, drop `NotGiven`/`None` values (`_json_value`, `_without_none`, `_form_data`), and decode: 204 or empty body → `None`, `application/json`/`+json` → parsed JSON, `text/*` (or `text=True`) → `str`, else `bytes`. Retries: connection errors and 408/409/429/5xx are retried only for GET/HEAD/OPTIONS, plus 429 on any request with a JSON body; delay honors `Retry-After` (capped 60s) else `0.5 * 2**attempt` capped at 8s. Errors: `APIError(status_code, body, request_id)` with a `.json` property, `APIConnectionError`.
- `resources/<tag>.py`: one `<Tag>` and one `Async<Tag>` class per contract tag, one method per operation. Positional parameters are path parameters, everything else is keyword-only, optional values default to `NOT_GIVEN`; every method also accepts `timeout=` and `extra_headers=`. Return types are `TypedDict`s in `types.py` named `<PascalTag><PascalMethod>Response` (325 TypedDicts today; camelCase wire names are preserved inside them, argument names are snake_case). Methods that take a whole JSON object are named `body=` (e.g. `upload.signed_url`, `images.update`, `deployments.update`); `models.predict` and `deployments.predict` are the only multipart operations and send `body["file"]` as a file part.
- `_cli_metadata.py`: `MULTIPART_FILES = {"deployments.predict": ["file"], "models.predict": ["file"]}`, computed from `multipart/form-data` bodies whose properties have `format: binary`.

**Naming rules** (generator `lib/openapi.ts`, `sdkIdentifier`/`sdkMethodCandidates`): resource = snake_case of the operation's first tag (`Storage Integrations` → `storage_integrations`); method = the contract's `x-sdk-method` override when present (13 operations use it, e.g. `merge_classes`, `adopt_images`, `selected_images`, `find_similar_images`), else the static path leaf after the resource segment (`/api/datasets/{owner}/{dataset}/class-stats` → `class_stats`), else `retrieve`/`list` for GET (item when the path has parameters and the summary does not start with list/view/search), else the verb map `post → create`, `patch`/`put → update`, `delete → delete`; collisions fall back to `<leaf>_<parent>`, then `<verb>_<leaf>`, then `_2`. Python reserved words get a trailing underscore (`from_`). Overrides come from `sdkMethod` in the route `contract.ts` files of the `portal` repo (`packages/ui/src/lib/openapi-contract.ts`), so a bad SDK method name is fixed upstream, never here.

**CLI** (`cli.py`, copied to `pkg/cli.py`; console script `ul`): `main(argv)` → no args / `help` prints usage; `version` prints `ultralytics-platform` and `ultralytics` versions; `cloud ...` → `dispatch()`; every other first token (`login`, `logout`, `train`, `val`, `predict`, `export`, `track`, `benchmark`, `settings`, `checks`, `cfg`, `copy-cfg`, `solutions`, ...) requires an importable `ultralytics`, sets `sys.argv = ["yolo", *args]`, and calls `ultralytics.cfg.entrypoint` — so `ul login API_KEY` is `yolo login` (validates via `Platform(...).account.summary()` and writes `api_key` into the shared `settings.json`). `dispatch()` builds `Platform(base_url=os.getenv("ULTRALYTICS_PLATFORM_URL", "https://platform.ultralytics.com"))`, discovers resources from `vars(client)` and operations from public bound methods (hyphenated names: `storage-integrations`, `usage-summary`), then: `assignments()` parses `key=value` tokens (rejects `--key value`; allows `name =value` splits; duplicates error), `defaults()` derives implicit verbs (bare resource → `list`; `retrieve` when its extra path identifiers are supplied), `describe()` turns the SDK signature + `get_type_hints` into `{types, choices, required, path}` descriptors via `kinds()` (skipping `timeout`/`extra_headers`), `parse()` coerces text to JSON kinds (`@file` / `@-` stdin for object/array/any-typed args, one stdin use max, `None`/`null` only for nullable, rejects NaN/Infinity, validates `Literal` choices, treats a missing path `owner` as optional), `open_inputs()` opens `@path` for `BinaryIO` args and for `MULTIPART_FILES` fields inside `body`, the owner is inferred with one `client.account.summary()["username"]` call, and `output()` prints JSON (indent 2), text, or raw bytes. Help (`help`, `--help`, `-h` as a bare token) prints the first docstring line per operation, or the full docstring minus `timeout`/`extra_headers` for one operation. Exit codes in `main()`: `APIError` → 1 (prints `API request failed (HTTP <status>): <body.error>` only, never the raw body), `APIConnectionError` → 1, `ValueError`/`OSError` → 2, `KeyboardInterrupt` → 130.

**Credentials** (`auth.py`, copied to `pkg/_auth.py`): `get_api_key()` mirrors `ultralytics.utils.get_user_config_dir` without importing it — `YOLO_CONFIG_DIR/Ultralytics`, else Linux `$XDG_CONFIG_HOME` or `~/.config/Ultralytics`, Windows `~/AppData/Roaming/Ultralytics`, macOS `~/Library/Application Support/Ultralytics`, falling back to `/tmp/Ultralytics` then `./Ultralytics` only when the preferred directory is neither present nor creatable — and returns `settings["api_key"]` from `settings.json` (a `""` after `yolo logout` deliberately yields no auth rather than a key from another location).

**Contract snapshot** (`openapi.json`, ~0.9 MB, OpenAPI 3.2.0, `info.version` = `0.1.39`, 60 paths / 86 operations, 13 tags, `servers[0]` = production): every operation is `application/json`; 21 operations declare optional auth (`security: [{}, {BearerAuth}]`) but the SDK still sends the header whenever a key resolves. `x-codeSamples` carry the Python examples shown at `platform.ultralytics.com/api/docs`.

**Releases.** The package version is `python.version` in `openapi.config.json` when set, else `openapi.json` `info.version`; both must be `MAJOR.MINOR.PATCH`. The Live job takes `max(contract version, current pyproject version)`: when the contract is newer it removes `python.version` so the SDK adopts it; when generated output changes without a newer contract (a generator or `cli.py`/`auth.py`/README change), it bumps the patch and writes `python.version`. To ship an SDK-only fix immediately instead of waiting for the daily sync, set `python.version` yourself and regenerate (PR #61 did exactly this: `openapi.config.json`, `sdk/python/pyproject.toml`, and the regenerated `_client.py`). `publish.yml` releases whenever `main`'s version is greater than PyPI's.

## Where to look

- CLI parsing, implicit verbs, help output, exit codes, owner inference → root `cli.py`, then regenerate so `pkg/cli.py` matches; the drift gate fails if you edit the copy. Cover behavior in `tests/test_cli.py` (real subprocess + loopback server), not by mocking `dispatch`.
- Saved-key discovery (`yolo login` settings, `YOLO_CONFIG_DIR`) → root `auth.py`, regenerate. Precedence between explicit key, env var, and provider is generated code in `pkg/_client.py` (`_resolve_api_key`, from `clientSource` in the generator) — change it in `ultralytics/openapi`.
- Transport bugs (retries, timeouts, header injection, response decoding, query/path serialization) → `pkg/_client.py` is generated from `lib/generators/python.ts` `clientSource` in `ultralytics/openapi`; fix there, let the Live sync land it here, and set `python.version` if it must publish now.
- Wrong or missing SDK method, argument name, type, `Literal` choices, docstring, or CLI help text → the contract. Argument docs and choices come from the OpenAPI schema; method names from `x-sdk-method`/path rules; all of it is generated in the `portal` repo (`scripts/generate-openapi.ts`, route `contract.ts` files) and reaches this repo through the Live job. Do not patch `resources/*.py` or `types.py`.
- New API endpoint → nothing to write here. The Live job regenerates and `tests/test_python_sdk.py::test_all_operations_serialize` automatically requires every contract operation to be callable on both clients. Add a canary call in `tests/live_readonly.py` only when live behavior is worth guarding (`expected_error(...)` for operations that cannot safely succeed).
- Package metadata (classifiers, `requires-python`, description, keywords, PyPI README) → `openapi.config.json` `python.*` and `README.python.md`, then regenerate; `sdk/python/pyproject.toml` and `sdk/python/README.md` are outputs.
- Contract refresh by hand → replace `openapi.json`, `sha256sum openapi.json > openapi.sha256`, regenerate, check the version rule above.
- Release or publish problems → `publish.yml` `check` job and the version arithmetic in `ci.yml` `Live` "Sync live OpenAPI contract" / "Apply generated changes".

## Gotchas

- `tests/live_readonly.py` is not read-only and is not collected by pytest. It needs `ULTRALYTICS_API_KEY`, runs against production, creates and deletes `sdk-ci-<timestamp>` projects/datasets/models, uploads `coco32.zip` from `ultralytics/assets`, paces requests at 0.75s, validates every JSON response against the `openapi.json` schemas with `jsonschema`, and raises on any 401 or 5xx, on a 403 outside `EXPECTED_FORBIDDEN`, or on an undocumented status. Operations that cannot succeed on the canary account (training start, export, deployment create, ...) are wrapped in `expected_error(...)` and must fail; the run also fails when the set of error-only operations drifts from those classifications. Run it only deliberately.
- `ULTRALYTICS_API_KEY=""` (empty) does not disable auth — `_resolve_api_key` treats an empty environment value as unset and falls through to the saved `yolo login` key (that is how `tests/test_cli.py` forces the settings path). Only an explicit `Platform(api_key="")` disables the header.
- `tests/test_cli.py` runs the CLI as `sys.executable -m ultralytics_platform.cli` with `YOLO_CONFIG_DIR=<tmp>` and `ULTRALYTICS_PLATFORM_URL=http://127.0.0.1:<port>`; without an installed package it fails with `No module named ultralytics_platform`, and it asserts that error output never echoes upstream bodies or private argument values.
- Only GET/HEAD/OPTIONS (and 429 on JSON bodies) are retried; multipart `predict` and every other POST/PATCH/DELETE go out exactly once. `max_retries=2` means up to three attempts.
- `ul` on macOS resolves to `/usr/bin/ul` (BSD underline filter) unless a virtualenv is activated first; `python -m ultralytics_platform.cli` always works. `ul login`/`ul logout` and all local commands need `ultralytics` installed in the same environment; `ul cloud ...` does not.
- Shell quoting: JSON arguments need single quotes (`'train_args={"epochs":1}'`), `@-` may be used by at most one argument per invocation, and binary fields must be `@path` (never stdin) even when nested inside a multipart `body` JSON.
- `bun run generate` also runs `ruff format` and header insertion on the output, so a locally edited `sdk/python` file will be silently reverted by the next regeneration — which is the point.
- `openapi.json` is ~0.9 MB and changes on almost every sync; keep unrelated files out of contract-update PRs and never hand-edit it (the `sha256sum --check` step fails first).
- `.generator/` is gitignored but `.generator/generated/` and `.generator/public/` are written during regeneration; delete the directory if a stale clone causes confusing diffs.
- `format.yml` will not reformat Python or Markdown for you here (`python: false`, `prettier: false`); run the pinned `uvx ruff@0.16.2 format --line-length 120` on `cli.py`, `auth.py`, and `tests/` yourself before pushing.

## Tests

- `tests/test_python_sdk.py`: `httpx.MockTransport` only. `test_priority_resource_requests` pins exact method/path/body for the README examples; `test_async_resource_tree` checks the absolute production URL; `test_all_operations_serialize` walks every public method on `Platform` and `AsyncPlatform` (`operations()`), fills required arguments by annotation (`required_arguments()`), and asserts the sorted `(METHOD, path)` set equals every operation in `openapi.json` — the contract and the generated clients cannot diverge without failing here; `test_api_error_details` checks `APIError.status_code`, `.body`, `.request_id`.
- `tests/test_cli.py`: one test, `test_cli_wire_and_auth`, drives the installed CLI through real subprocesses against a `ThreadingHTTPServer` on `127.0.0.1` that records method, path, headers, and body: saved-settings vs environment key precedence, implicit `list`/`retrieve`, help variants, exit code 2 for local input errors (unknown argument, bare non-boolean, non-finite numbers, duplicate stdin), exit code 1 with sanitized messages for HTTP 401/422, `False`/`0`/`null`/`"None"` value semantics, `@file` and `@-` JSON inputs, and multipart `@path` uploads.
- `tests/live_readonly.py`: the production canary described in Gotchas; `validate_sdk()` installs a `pace_request` hook, `exercise_api()` runs every operation, `cleanup_resource`/`cleanup_created` make teardown idempotent, and the final gate compares error-only operations against the `expected_error` classifications. Requires `jsonschema` and `referencing`.
- No `conftest.py`, no fixtures beyond `tmp_path`, no network in the pytest suite. CI runs `pytest tests -v` on Python 3.11 and 3.14 after a Git-subdirectory install.

## Conventions

- Ultralytics-owned PyPI packages use `MAJOR.MINOR.PATCH` versions only; no suffixes.
- License headers (`# Ultralytics 🚀 AGPL-3.0 License - https://ultralytics.com/license`) are added automatically by Ultralytics Actions — don't add or revert them manually. Generated files receive the same header from the generator (`header` in `openapi.config.json`, applied by `scripts/headers.ts`).
- Google-style docstrings, `from __future__ import annotations` for modern type hints, line length 120; formatting is checked by `ci.yml` with the pinned `uvx ruff@0.16.2` (`format.yml` runs with `python: false`, so nothing reformats Python on PR branches) and the generator formats its own output.
